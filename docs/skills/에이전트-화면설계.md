# AGENT HQ 화면 디자인 원칙

이 원칙은 2026-10-01 같은 빵집 페이지를 네 조건(예전 지침 Sonnet, 새 지침 Sonnet, 새 지침 Opus, Codex Sol)으로 만들어 엔진 캡처로 비교한 결과에서 나왔다. 무난한 기본형은 피한다. 다만 개성은 장식의 개수가 아니라 정보 구조·글자·색의 일관된 선택에서 나오고, 날짜·장소·시간표를 찾는 화면이면 읽기 쉬운 배치가 우선이다. 화려함 때문에 내용이 안 보이거나 깨지면 더 큰 실패다.

같은 날 책방·플리마켓 시험과 Codex(GPT)의 비판으로 고친 점도 담았다. 팀 지침(src/팀.js)과 이 문서가 다르면 팀 지침을 따른다.

## 1. 먼저 방향을 정한다
- design/화면설계.md 에 미적 방향 한 줄을 적는다. 예: "밤에 불 켜진 골목 책방", "행사 안내판처럼 날짜·시간이 먼저 읽히는 장터". 예시는 따라 만들 기본형이 아니다. 앞선 결과와 색·배치·장식이 겹치면 다른 방향을 본다.
- 이 프로젝트만의 기억에 남는 요소 하나를 정한다. 예: 직접 그린 SVG 그림, 내용에서 나온 작은 기능(지금 영업 중 표시), 지그재그 구역 경계. 01·02 같은 큰 테두리 번호는 쓰지 않는다. 종이 질감·테이프·도장·기울인 카드·손글씨를 한 페이지에 다 모으지 않는다 (이 엔진에서 반복된 버릇).
- 주된 색 하나 + 날카로운 강조색 하나. 회색·파랑 기본값, 아무 데나 쓰는 파랑·보라 그라데이션은 쓰지 않는다.

## 2. 글자
- 가장 큰 글씨는 방문자가 먼저 알아야 할 정보에 준다. 페이지 이름이 늘 주인공은 아니다.
- 제목은 과감하게: clamp(2.5rem, 6vw, 5rem) 정도, 줄간격 1.1 안팎, 자간을 살짝 좁힌다. 390px 에서 제목 때문에 핵심 정보가 밀려나지 않게 한다.
- 본문은 16px 안팎, 줄간격 1.6~1.8, 한 줄 40~70자. 12px 보다 작은 글자는 쓰지 않는다.
- 숫자(가격·시간)는 tabular-nums 로 줄을 맞춘다.
- 굵기는 400·700만 쓰지 말고 500·600 도 써서 위계를 나눈다.
- 글꼴 이름을 적을 때 이 PC·방문자 PC에 실제로 있는지 생각한다. 없는 글꼴만 적으면 제목이 바탕(Batang), 본문이 맑은 고딕으로 바뀌어 딱딱해진다. 엔진이 글꼴 묶음을 주면 그것을 쓰고, 없으면 굵기·크기·자간과 SVG 글자 장식으로 개성을 낸다.

## 3. 배치
- 흰 바탕에 같은 모양 카드만 세로로 쌓기, 모든 것 가운데 정렬, 회색 테두리 상자 반복을 피한다.
- 비대칭 2단, 겹침, 풀폭 색 구역(예: 짙은 갈색 영업시간 띠), 크기 대비로 리듬을 만든다.
- 콘텐츠 최대 폭(1100~1300px)을 두고, 위아래 여백은 아래를 조금 더 크게.
- 390px 첫 화면에는 방문 여부를 판단할 정보(날짜·장소·여는 시간·지금 상태)와 가장 중요한 행동을 둔다. 아래로 가는 버튼만 두는 것은 우선순위를 지킨 것이 아니다.
- 모바일(390px)에서 4열 이상 표는 행마다 카드 하나로 바꾼다(이름·가격을 위에, 설명·성분을 아래에). 글자가 한 글자씩 세로로 쌓이면 실패다.
- 모바일 반복 목록(셀러·메뉴·일정)은 한 열로 바꾸는 데서 끝내지 않고 훑어볼 수 있게 압축한다. 이름·시간·핵심 정보는 늘 보이고, 긴 설명과 장식만 접거나 줄인다.
- SVG 안 글자는 화면에 실제로 보이는 크기로 본다. 휴대폰에서 작아지는 길 안내는 그림 밖 글로 쓰고, 약도에는 도착 지점과 핵심 표지만 남긴다.

## 4. 움직임
- 움직임은 상태 변화나 사용자 행동을 설명할 때 쓴다: 첫 화면 요소가 순서대로 나타나기(animation-delay 80~120ms 간격), 버튼·카드 hover 와 active(translateY(1px)) 반응, 스크롤하면 나타나는 구역 등. 개수를 채우려고 넣지 않는다.
- 날짜·시간·가격·길 안내 글자는 움직이지 않는다. 끝없이 반복되는 장식 움직임은 하나까지만.
- transform 과 opacity 만 움직인다. 200~300ms, ease-out 계열.
- prefers-reduced-motion: reduce 이면 모두 끈다.
- 스크롤 등장 안전장치(필수): 내용은 기본으로 보이게 두고, JS 가 돌 때만 html 에 class 를 붙여 잠깐 숨긴다. IntersectionObserver 의 threshold 는 0 으로 두고 rootMargin 으로 아래쪽을 줄이지 않는다 (줄이면 맨 아래 내용이 끝내 안 나타날 수 있다). 스크롤 위치로 지나친 요소도 보이게 하는 대비책을 함께 둔다. 화면보다 큰 덩어리(긴 표, 목록 전체)는 통째로 숨기지 말고 행·카드 단위로 나눈다. 비교에서 threshold 0.12 로 큰 표를 숨긴 페이지는 폰에서 메뉴가 끝내 나타나지 않았다.

## 5. 배경과 깊이
- 평평한 단색만 쓰지 말고 아주 옅은 질감(점 무늬, 종이결, 그레인)이나 방사형 그라데이션을 깐다.
- 그림자는 배경 색조를 섞어 쓴다(검정 반투명 대신 갈색·초록 계열).
- 외부 이미지를 못 쓰면 인라인 SVG 로 일러스트·무늬·지도를 그린다. 그림에는 aria-hidden 또는 의미 있는 대체 글을 단다.

## 6. 상태와 접근성
- 모든 버튼·링크에 hover, active, focus-visible 모양을 준다.
- "본문 바로가기" 링크는 평소엔 화면 밖에 두고 :focus 일 때만 보이게 한다(비교에서 화면에 그대로 드러난 사례가 있었다).
- 글자와 배경 대비를 충분히(본문 4.5:1 이상). 어두운 띠 위의 흐린 글씨를 조심한다.
- 예시 정보는 맨 위 안내 띠 한 줄과, 예시 내용이 든 구역마다 한 번(제목 옆 작은 표시)이면 충분하다. 항목·카드마다 배지를 붙이지 않는다.

## 7. 끝내기 전 점검
- "이대로면 누구나 만드는 무난한 페이지인가?" 그렇다면 장식을 더하기 전에 정보 구조·배치·글자 선택부터 바꿔 본다.
- 390px 첫 화면만 보고 방문 여부를 판단할 수 있는지 확인한다.
- 엔진 캡처(.hq-screens/)를 열어 PC 와 모바일을 모두 본다: 잘림, 넘침, 어색한 줄바꿈(가게 이름이 한 글자 남고 넘어감), 흐리게 남은 구역, 너무 작은 글자.
- 보지 않은 것을 봤다고 쓰지 않는다. 바꾼 부분은 다음 검증의 캡처에서 확인된다고 note 에 적는다.
