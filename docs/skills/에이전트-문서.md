# AGENT HQ 문서 만들기 (회의록·보고서·계획서)

팀이 Markdown 원고를 쓰면 엔진이 한글 문서(HWPX)로 만든다. 첫 회의록 시험(2026-10-01)은 원고 8줄을 그대로 옮겨 한 쪽의 70%가 비었고, 안건별 논의·담당·기한·후속 조치가 없었다. 원고를 보존하라는 말은 "대장이 준 사실을 바꾸지 말라"는 뜻이지 "그것만 쓰라"는 뜻이 아니다. 문서 종류마다 아래 항목을 갖추고, 대장이 주지 않은 사실은 지어내지 않고 "(미정)" 또는 "(확인 필요)"로 칸을 남긴다.

## 1. 문서 종류별 필수 항목
- 회의록: 기본 정보 표(일시·장소·참석·작성자), 안건 목록, 안건별 논의 요약(누가 무엇을 말했는지 2~4줄), 결정 사항(번호·내용·담당·기한 표), 후속 조치 표(할 일·담당·기한·상태), 다음 회의(일시·안건), 첨부·참고.
- 보고서(업무보고): 한 줄 요약, 배경, 추진 현황(표: 항목·목표·실적·비율), 문제와 대응, 다음 계획(표: 일·담당·기한), 요청 사항.
- 계획서: 목적, 대상·범위, 추진 일정(표: 단계·기간·산출물), 역할 분담, 예산(있으면 표), 기대 효과(숫자 목표), 위험과 대응.
- 기안·통지·보도자료 등 다른 서식은 엔진 서식 이름을 따르되, 위처럼 "누가·무엇을·언제까지"가 드러나게 쓴다.

## 2. 형식
- 기본 정보, 결정, 후속 조치, 일정, 예산은 표로 쓴다. 긴 문장 목록으로 나열하지 않는다.
- 개조식(짧은 명사형 문장)으로 쓰고, 한 항목은 두 줄을 넘기지 않는다.
- 제목 위계는 3단계까지 (1. → 가. → 1)). 같은 수준의 제목은 같은 모양으로.
- 짧은 문서는 1~2쪽에 담는다. 표지·목차는 대장이 요청했거나 5쪽 넘는 문서에만.
- document-typography-design 스킬이 있으면 글자 크기·위계·표·여백은 그 기준을 따른다.

## 3. 끝내기 전
- 대장이 준 숫자·날짜·이름이 원고와 똑같은지 다시 대조한다. 엔진도 재변환 내용으로 숫자·날짜를 대조한다.
- 빈 칸으로 남긴 항목(미정·확인 필요)을 note 에 모아 적는다. 대장에게 물어야 할 것이면 needs_decision 으로.
- 보고서 JSON 의 documents 에 원고와 서식(preset)을 적는다. 엔진이 HWPX 와 미리보기를 만든다.
