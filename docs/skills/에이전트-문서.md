# AGENT HQ 문서 만들기 (회의록·보고서·계획서)

팀이 Markdown 원고를 쓰면 엔진이 한글 문서(HWPX)로 만든다. 첫 회의록 시험(2026-10-01)은 원고 8줄을 그대로 옮겨 한 쪽의 70%가 비었고, 안건별 논의·담당·기한·후속 조치가 없었다. 원고를 보존하라는 말은 "대장이 준 사실을 바꾸지 말라"는 뜻이지 "그것만 쓰라"는 뜻이 아니다. 문서 종류마다 아래 항목을 갖추고, 대장이 주지 않은 사실은 지어내지 않고 "(미정)" 또는 "(확인 필요)"로 칸을 남긴다.

## 1. 문서 종류별 필수 항목
- 회의록: 기본 정보 표(일시·장소·참석·작성자), 안건 목록, 안건별 논의 요약(누가 무엇을 말했는지 2~4줄), 결정 사항(번호·내용·담당·기한 표), 후속 조치 표(할 일·담당·기한·상태), 다음 회의(일시·안건), 첨부·참고.
- 보고서(업무보고): 한 줄 요약, 배경, 추진 현황(표: 항목·목표·실적·비율), 문제와 대응, 다음 계획(표: 일·담당·기한), 요청 사항.
- 계획서: 목적, 대상·범위, 추진 일정(표: 단계·기간·산출물), 역할 분담, 예산(있으면 표), 기대 효과(숫자 목표), 위험과 대응.
- 기안·통지·보도자료 등 다른 서식은 엔진 서식 이름을 따르되, 위처럼 "누가·무엇을·언제까지"가 드러나게 쓴다.

## 2. 형식 — 한글 양식처럼
재시험(2026-10-01)은 항목은 갖췄지만 웹 문서처럼 보였다: 손으로 매긴 "## 1." 제목, 구분/내용 2열 표, 표와 본문에 같은 안건 두 번, 칸이 전부 (미정)인 표. 한글 회의록·보고서는 이렇게 읽힌다.
- 맨 위 기본 정보는 4열 표로: `| 회 의 명 | … | 작 성 자 | … |` 다음 줄 `| 일    시 | 2026. 9. 30. 14:00 | 장    소 | … |`, `| 참 석 자 | … | 안    건 | … |`. 라벨은 글자 사이를 띄워 칸 폭을 맞춘다. 표 위에 "기본 정보" 같은 제목을 달지 않는다.
- 본문 제목은 번호 없이 `## 회의 개요`, 항목은 `- 내용`, 하위 항목은 들여쓴 `- 내용`. 엔진이 1. → 가. → 1) 로 바꾼다. 번호를 직접 쓰면 두 번 매겨진다.
- 결정·후속 조치·일정·예산은 담당·기한 같은 값이 있을 때 표로 쓴다. 칸이 전부 (미정)이면 표 대신 `- 담당·기한: (미정)` 한 줄로.
- 표에 쓴 내용(일시·장소·안건)을 본문에서 다시 쓰지 않는다.
- 개조식(짧은 명사형 문장)으로 쓰고, 한 항목은 두 줄을 넘기지 않는다.
- 회의록·보고서·기안문은 documents 에 `"approval":["담당","검토","대장"]` 을 넣어 오른쪽 위 결재란을 단다 (대장이 다른 직위를 주면 그것). 본문 글꼴은 엔진 기본 명조.
- 요일은 확실할 때만 `2026. 9. 30.(수)` 처럼 붙인다.
- 짧은 문서는 1~2쪽에 담는다. 표지·목차는 대장이 요청했거나 5쪽 넘는 문서에만.
- document-typography-design 스킬이 있으면 글자 크기·위계·표·여백은 그 기준을 따른다.

## 2-1. 기관 양식 채우기 (사업계획서·연구개발계획서·결과보고서·신청서)
기관이 준 양식은 정해진 표·번호 체계·칸에 딱 맞게 들어가야 한다. 새 문서를 만들면 표 병합, 글꼴, 여백, 쪽 구성이 모두 달라져 쓸 수 없다.
- 양식은 새로 만들지 않고 채운다. 대장이 첨부한 양식(attachments/양식.hwp 또는 .hwpx)을 엔진이 Markdown 으로 바꿔 둔다(attachments/양식.hwp.md). 그 파일을 복사해 내 작성본(예: 계획서.md)으로 고친다.
- 고치는 것은 칸 안의 값과 본문 문단뿐이다. 목차 번호·제목, 표, 행·열 수, 순서는 그대로 둔다. 표 칸을 합치거나 나누지 않는다.
- 양식의 작성요령·예시 문구("※ ~를 작성", "(예시)")는 양식이 지우라고 한 곳만 지우고, 그 자리를 내용으로 채운다.
- 보고서 JSON: `"documents":[{"template":"attachments/양식.hwp","from":"계획서.md","to":"계획서.hwp"}]` (결과는 양식과 같은 형식). 엔진이 원본 파일에 내 글만 넣고, 목차·표가 양식과 같은지 확인한다. 다르면 실패로 돌아온다.
- 문체는 개조식: `◦ 핵심 한 줄` 아래 `- 근거·수치 한두 줄`. 문장 끝은 "~함·~임·~예정". 한 항목은 두 줄을 넘기지 않는다.
- 목표는 숫자와 측정 방법으로 쓴다(지표·목표값·측정 기관 또는 기준). 일정은 월 단위 표, 사업비는 양식의 단위(천원·백만원)와 합계식을 그대로 지킨다.
- 표·그림에는 양식대로 `[표. 제목]`, `[그림. 제목]` 을 붙이고, 출처가 있으면 아래에 `※ 출처:` 를 단다.
- 대장이 주지 않은 실적·매출·인원·기관명·연락처는 지어내지 않는다. "(미정)" 또는 "(확인 필요)" 로 남기고 note 에 모아 적는다.
- 칸 크기와 쪽 수 제한이 있는 양식은 그 안에 들어가게 줄인다. 길게 늘이면 원본 양식의 쪽 구성이 깨진다.

## 3. 끝내기 전
- 대장이 준 숫자·날짜·이름이 원고와 똑같은지 다시 대조한다. 엔진도 재변환 내용으로 숫자·날짜를 대조한다.
- 빈 칸으로 남긴 항목(미정·확인 필요)을 note 에 모아 적는다. 대장에게 물어야 할 것이면 needs_decision 으로.
- 보고서 JSON 의 documents 에 원고와 서식(preset)을 적는다. 엔진이 HWPX 와 미리보기를 만든다.
